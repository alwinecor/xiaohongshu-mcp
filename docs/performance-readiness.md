# 搜索与详情读取性能修复

浏览器读取会等待网页资源和应用数据。此前搜索等待整页稳定，详情等待 load 事件，无关图片、统计请求和页面变化也可能拖慢返回，甚至耗尽搜索超时。

## 调整

- 搜索数据就绪条件与原有页面稳定条件并行等待；任一条件满足即可继续，取消剩余等待。空结果保留原有稳定条件。
- 详情等待正文与首批评论，或已渲染文字的错误提示；保留全部评论加载开关。
- 已完成就绪检查后，直接检查错误容器，避免正常页面轮询不存在的容器。
- 浏览器启动、跳转、数据就绪和提取阶段记录 `performance` 日志，包含 `phase`、`elapsed_ms`，新增耗时日志不携带凭据和笔记内容。
- Cookie 路径测试同时设置 `TMPDIR`、`TMP`、`TEMP`，兼容 Windows。

## 验证

```powershell
go test ./...
go test -tags integration ./xiaohongshu -run '^TestReadiness' -count=1
```

第二条命令使用本地 HTTP 测试页及项目浏览器，不访问小红书，也不需要登录。首次运行可能下载项目内置浏览器。覆盖慢图片、延迟正文、默认评论、空搜索、延迟错误文字及取消行为。

一次真实只读对照中，同一关键词搜索加单篇详情由约 29.2 秒降至 13.7～16.6 秒，正文、图片数量和默认十条评论均完成核对。该数据是本地样本，不能视为固定时延承诺，网页和网络波动仍然存在。

## 目录约定

开发目录只存放 Git 管理的源码；个人工具链、缓存和本机测试材料放在被忽略的 `.local/`。部署目录单独存放程序、浏览器缓存、配置、日志和凭据。不要把 Cookie、Tunnel 运行密钥或个人运行日志提交到仓库。
