# 搜索与详情读取性能修复

浏览器读取会等待网页资源和应用数据。此前搜索等待整页稳定，详情等待 load 事件，无关图片、统计请求和页面变化也可能拖慢返回，甚至耗尽搜索超时。

## 调整

- 搜索数据就绪条件与原有页面稳定条件并行等待；任一条件满足即可继续，取消剩余等待。空结果保留原有稳定条件。
- 详情等待正文与首批评论，或已渲染文字的错误提示；保留全部评论加载开关。
- 已完成就绪检查后，直接检查错误容器，避免正常页面轮询不存在的容器。
- 浏览器启动、跳转、数据就绪和提取阶段记录 `performance` 日志，包含 `phase`、`elapsed_ms`，新增耗时日志不携带凭据和笔记内容。
- Cookie 路径测试同时设置 `TMPDIR`、`TMP`、`TEMP`，兼容 Windows。

## 验证

```powershell
go test ./...
go test -tags integration ./xiaohongshu -run '^TestReadiness' -count=1
```

第二条命令使用本地 HTTP 测试页及项目浏览器，不访问小红书，也不需要登录。首次运行可能下载项目内置浏览器。覆盖慢图片、延迟正文、默认评论、空搜索、延迟错误文字及取消行为。

一次真实只读对照中，同一关键词搜索加单篇详情由约 29.2 秒降至 13.7～16.6 秒，正文、图片数量和默认十条评论均完成核对。该数据是本地样本，不能视为固定时延承诺，网页和网络波动仍然存在。

## 账号类只读调用

- 登录检查：已认证状态直接读取，游客状态保留页面稳定确认，避免把认证初始化中的 `guest` 误判为未登录。
- 通知未读数：等 `isUnreadCountInitialized`，再读取计数；初始零值不代表请求完成。
- 主页：检查用户及目标标签的请求状态已 `resolved`，并区分加载中与有效空列表。读取本人侧栏链接直接导航到目标标签，按主框架的新 loader 等待 DOMContentLoaded，排除旧文档和子框架事件。
- 主页初始状态既可能是普通对象，也可能是 Vue 的 `value`/`_value` 包装；就绪判断与内容读取须同时支持这三种形式。

额外回归测试：

```powershell
go test -tags integration ./xiaohongshu -run '^TestAccountReadiness' -count=1
```

覆盖暂态游客、延迟未读计数、初始空列表、标签渲染、普通初始对象、新旧文档切换、导航失败清理和取消。

## 批量评论加载

- “无评论”和 `THE END` 使用即时 DOM 查询，只接受可见标志；已有一级评论时忽略残留空提示。
- 每轮滚动后统一等待评论数量变化或有效终止标志，最长三秒。单轮超时继续后续有限尝试，不将初始空列表或 `hasMore=false` 当成完成。
- 到底后仍保留用户要求的子回复展开。点击后单独等待所在楼层的评论项增加，最多十秒；按钮消失或已有 `THE END` 不代表子回复请求完成。
- 子回复等待失败与取消逐层返回错误，避免把未完成的读取作为成功结果。新增 `detail_comments` 阶段耗时日志。

回归测试：

```powershell
go test -tags integration ./xiaohongshu -run '^TestCommentLoading' -count=1
```

覆盖真实空提示、到底标志、隐藏标志、残留空提示、延迟结果、跨过单轮等待上限的慢分页、按钮先消失的慢子回复、子回复超时和取消。测试使用本地页面，不访问小红书。

一次本地只读对照中，同一篇显示约 396 条评论的笔记，加载 60 条一级评论由 36.1 秒降至 18.8 秒，100 条由 53.0 秒降至 21.3 秒。最终构建复测分别为 12.4 秒和 18.1 秒。原小样本加载 20 条由 18.3 秒降至最终构建的 8.9 秒，加载至底部的 25 条由 21.0 秒降至 10.9 秒。各场景的正文、图片数、一级评论与已加载子回复 ID 完成核对，未发现基线 ID 缺失。测试期间小样本新增一条子回复，因此最终回复数略增。数据为有限前后样本，不包含 ChatGPT 云端或 tunnel 耗时，也不代表完整抓取笔记标示的全部评论。

## 通知列表

- 使用新文档的 `DOMContentLoaded` 屏障，避免读取上一页状态；不再等待无关图片的 `load`。
- 页面初始化完成后即可切换目标分区，不等待无关默认分区的列表请求；过早切换会被初始化重置，因此保留 `isUnreadCountInitialized` 与默认分区索引的初始化检查。
- 对目标分区检查 `activeTabKey`、`isFetching`、非空分页游标及列表结构。支持普通字段和 Vue `value`/`_value` 包装；初始空列表与初始 `false` 不作为完成信号。
- 滚动后短时观察分页变化。未触发请求时继续有限滚动，已开始请求时等待列表、游标或终止状态更新；保留二十轮上限，超时明确返回错误。
- 被过滤的通知不占 `limit` 名额，必要时继续加载下一页。
- 导航、标签定位、数据等待和滚动均绑定调用上下文。新增文档、初始化、标签切换、目标数据就绪、分页与提取阶段日志。

```powershell
go test -tags integration ./xiaohongshu -run '^TestNotificationReadiness' -count=1
```

测试在浏览器中拦截并提供静态页面，全部请求在本地处理，不访问小红书。覆盖慢图片、旧文档、有效空列表、初始空状态、Vue 包装、延迟标签、无关默认请求挂起、多次滚动后才触发分页、过滤后数量上限以及取消。

一次本地交替对照中，每个分区各运行三次旧版和新版。评论和 @、赞和收藏、新增关注的中位耗时分别由 5.05、9.03、7.63 秒降至 4.24、5.76、6.60 秒，前后返回内容完全相同。真实账号样本仅零至一条通知，大量通知分页由本地页面回归覆盖；这些数据不包含模型和 tunnel 开销，也不能视为长期时延保证。本轮保留此范围的改动，不进一步扩大优化。

## 目录约定

开发目录只存放 Git 管理的源码；个人工具链、缓存和本机测试材料放在被忽略的 `.local/`。部署目录单独存放程序、浏览器缓存、配置、日志和凭据。不要把 Cookie、Tunnel 运行密钥或个人运行日志提交到仓库。
